# Database Seeding Documentation

Комплексная система заполнения базы данных тестовыми данными для разработки и тестирования.

## Запуск Seed

### Локально
```bash
cd backend
npm run seed
```

### Docker
```bash
# Через Docker Compose
docker-compose exec backend npm run seed

# Или через Makefile
make seed
```

## Очистка и повторное заполнение

Скрипт автоматически очищает базу в режиме разработки перед заполнением:

```bash
# Установить NODE_ENV и запустить
NODE_ENV=development npm run seed
```

## Production

⚠️ **ВАЖНО**: В production режиме скрипт НЕ удаляет существующие данные, а только:
- Обновляет достижения (upsert)
- Обновляет промокоды (upsert)

Пользователи и поездки в production не создаются автоматически.

## Расширение Seed

Для добавления новых тестовых данных отредактируйте `prisma/seed.ts`:

```typescript
// Добавить больше пассажиров
const passenger4 = await prisma.user.create({
  data: {
    phoneNumber: '+77041234567',
    passwordHash: hashedPassword,
    firstName: 'Новый',
    lastName: 'Пассажир',
    role: UserRole.PASSENGER,
    passengerProfile: {
      create: {
        loyaltyPoints: 0,
        loyaltyTier: 'BRONZE',
      },
    },
  },
});

// Добавить больше поездок
const ride5 = await prisma.ride.create({
  data: {
    passengerId: passenger4.id,
    // ... данные поездки
  },
});
```

## Troubleshooting

### Ошибка: "Unique constraint failed"
Скрипт пытается создать дублирующиеся данные. Решение:
```bash
# Очистить базу вручную
npx prisma migrate reset

# Или удалить только данные
npx prisma db push --force-reset
```

### Ошибка: "bcryptjs not found"
Установить зависимости:
```bash
npm install bcryptjs
npm install -D @types/bcryptjs
```

### Seed не запускается в Docker
Проверить, что база данных готова:
```bash
# Проверить статус контейнеров
docker-compose ps

# Проверить логи postgres
docker-compose logs postgres

# Подождать healthcheck и повторить
docker-compose exec backend npm run seed
```

## Best Practices

1. **Всегда используйте seed в development** для консистентных тестовых данных
2. **Не запускайте seed в production** без явной необходимости
3. **Обновляйте seed при изменении схемы** для актуальности данных
4. **Используйте реалистичные данные** для Алматы (координаты, адреса)
5. **Добавляйте edge cases** (неверифицированный водитель, pending rides)
6. **Документируйте новые тестовые данные** в этом файле
